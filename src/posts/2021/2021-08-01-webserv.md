I built webserv, an HTTP/1.1 server in C++98, for the École 42 curriculum. It
reads an nginx-style configuration describing several virtual servers, listens
on their addresses with non-blocking sockets, and serves static files, directory
listings, redirects, PUT uploads and CGI output. There are no third-party
libraries: the config parser, request parser, response streaming and CGI
environment sit directly on the POSIX socket API.

The core is a single-threaded poll() loop. Listening sockets are deduplicated by
(host, port), so virtual servers on one address share a socket, and each client
fd is polled for POLLIN or POLLOUT depending on whether it is reading a request
or sending a response. The request parser is an explicit state machine (start
line, headers, Content-Length body or chunked body), so a request split across
many recv() calls is handled the same way as one that arrives whole. Bodies are
streamed to a mkstemp temporary file rather than held in memory; that file is
then dup2'd to a CGI script's stdin or renamed into the upload directory for
PUT. Responses go out 1 KiB per POLLOUT event through an IResponse interface,
and CGI output is re-encoded as chunked transfer because its length is unknown
up front.

I chose to validate the configuration fully at load time: unknown or duplicated
keys, a location without root, redirect or cgi, PUT without upload_store, non-
existent paths and duplicated server names are all rejected before any socket is
opened. Location matching follows nginx: by extension, then exact URI, then
longest prefix; the server is picked by address and Host header.

The code is about 2,800 lines in 47 files, compiled with -Wall -Wextra -Werror
-std=c++98 by a Makefile with automatic dependency generation. There is no
automated test suite; the 42 tester binaries, sample sites and CGI scripts are
included.

Limitations: CGI runs synchronously (waitpid blocks the loop), there are no
connection timeouts, and the code targets macOS (st_mtimespec, strlcpy), so a
Linux build needs small changes.
