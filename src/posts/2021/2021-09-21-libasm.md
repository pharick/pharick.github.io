For the École 42 libasm project I wrote thirteen functions in x86-64 assembly
(NASM, Intel syntax, Mach-O output) and packaged them as libasm.a with a C
header so they can be called like their libc counterparts. The mandatory set is
strlen, strcpy, strcmp, strdup and wrappers for the read and write system calls;
the bonus set adds strchr, isspace, atoi_base and four operations on a singly-
linked list: push_front, size, sort and remove_if.

The most instructive part was the system-call wrappers. ft_write and ft_read
load the BSD syscall numbers (0x2000004 and 0x2000003) into rax and execute
syscall; macOS reports failure by setting the carry flag, so on jc the routine
calls ___error to obtain the address of errno, stores the error code there and
returns -1, exactly like the libc wrappers. The test program compares return
values and errno against write and read for a NULL buffer and a bad file
descriptor.

Everything else is about respecting the System V AMD64 ABI by hand: arguments in
rdi, rsi, rdx and rcx, the result in rax, an odd number of pushes before calling
malloc to keep the stack 16-byte aligned, and underscore-prefixed symbols for
Mach-O. strcmp compares bytes as unsigned so values above 0x7F sort after ASCII,
which I test with a \200 case. atoi_base is composed from the other routines
(strlen for the base length, isspace to skip whitespace, strchr to map a digit
to its index). list_sort is a bubble sort that swaps data pointers and calls the
C comparator through a register; list_remove_if unlinks matching nodes and calls
the user's free function and then free, saving every live register around each
callback.

make test and make test_bonus build the two interactive drivers with clang and
run them. Limitations: the code is macOS-only (a Linux port needs elf64 output,
different syscall numbers and __errno_location), atoi_base does not validate its
base, and there is no overflow checking.
