I built cub3d for the École 42 cub3D project: a Wolfenstein-style first-person
renderer in C on MiniLibX that loads a level from a `.cub` file, draws textured
walls and sprites, and lets you walk through the map with WASD and the arrow
keys. It runs on macOS only, on top of the Swift/Metal MiniLibX build that is
vendored in the repository.

The rendering core is a per-column DDA raycaster. For each screen column I
derive a ray from the camera direction and plane vectors, step it through the
grid one cell boundary at a time, and use the perpendicular distance to the hit
wall for the column height, which avoids fish-eye distortion. The DDA also
reports which of the four faces was hit, so each face gets its own texture, and
I mirror the horizontal texture coordinate on two of the faces so nothing is
drawn backwards. Sprites were the more interesting part: I record the wall
distance of every column in a z-buffer, sort the sprites far-to-near each frame,
project them through the inverse camera matrix, and draw each vertical stripe
only where the sprite is closer than the wall behind it.

Before rendering anything I validate the map: only `0 1 2 N S E W` and spaces
are allowed, every walkable cell must be enclosed by non-space neighbours inside
the map, and there must be exactly one player. That guarantees the ray loop
always terminates on a wall. All failures go through one error function and one
cleanup function that frees whatever was actually allocated, so every exit path
releases its resources.

Frames are drawn into an off-screen image and swapped with a second one;
movement is applied per axis so the player slides along walls. A `--save` flag
renders a single frame and writes it as a 32-bit BMP with a hand-built header.

The code follows the 42 Norm: short functions, no globals, an own libft instead
of libc helpers. Limitations: macOS only, XPM textures whose height is a power
of two, unknown config lines are silently ignored, and there are no automated
tests.
