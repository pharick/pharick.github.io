libftpp is my implementation of École 42's `libftpp` subject: a C++23 static
library whose component list is fixed by the subject (object pool, serialization
buffer, memento, observer, singleton, state machine, thread-safe iostream and
queue, thread wrapper, worker pool, persistent worker, TCP
message/client/server, 2D/3D vectors, a coordinate hash and Perlin noise). What
was mine to decide was how carefully each piece handled its failure modes.

The networking layer is where that mattered most. `Message` is a framed
protocol, `[int32 size][int32 type][payload]`, always little-endian, with a 16
MB cap and a refusal to serialize a message that has been partially read, since
that would desync the stream. `Client` and `Server` run non-blocking sockets:
each connection accumulates bytes in its own receive buffer until a full frame
is present, sends loop until every byte is written, and a small exception
hierarchy separates "no data yet" from "peer closed" from "protocol violated".

In `Pool<T>` I construct objects with placement `new` into aligned raw storage,
give `acquire()` the strong exception guarantee, and hand out RAII handles that
carry a `shared_ptr<bool>` liveness token, so a handle that outlives its pool
becomes a no-op instead of a use-after-free. The threading components never hold
a lock while user code runs: workers release the mutex before calling a job, and
the persistent worker snapshots its task map with `ranges::to` and runs the
copy.

Every component states whether it is thread-safe. The test suite is roughly
twice the size of the library (about 7,000 lines, 210 Catch2 cases): it uses
real producer/consumer threads and real sockets on localhost rather than mocks,
and one runnable example exists per component. Everything builds with `-Wall
-Wextra -Werror` from a plain Makefile.

Limitations I know of: the server polls each client with `recv` on every
`update()` rather than waiting in `poll()`, the queue has no blocking pop,
networking is IPv4/POSIX only, and the persistent-worker tests are timing-
sensitive.
