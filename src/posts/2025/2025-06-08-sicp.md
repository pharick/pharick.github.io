I am working through *Structure and Interpretation of Computer Programs* in
Racket, one file per exercise. As of September 2025 the repository covers 128
exercises from chapters 1 to 3 in 132 Racket files, plus a Python version of the
procedural-pairs exercise. Files use `#lang racket` and pull in the `sicp`
package only where the book's primitives (or `sicp-pict` for the picture
language) are needed.

Most files end with rackunit assertions - 405 checks across 104 files - so each
solution is a runnable test rather than a transcript. The Miller-Rabin test, for
example, is checked against the Carmichael numbers that defeat the plain Fermat
test, and the constraint-propagation converter is tested in both directions.

The larger solutions are where I went past the book's minimum. For exercise 3.26
I implemented the table as a left-leaning red-black tree on mutable pairs, with
rotations, colour flips and a comparator parameter, and then reused it as the
memoization cache in 3.27. The deque in 3.23 is a doubly linked structure with
O(1) operations at both ends. Exercise 2.87 carries the full generic arithmetic
system - dispatch tables on Racket hashes, a type tower with `reachable?` and
`highest-type`, `apply-generic` raising arguments to a common type - with the
polynomial package installed on top. The Huffman exercises implement decoding,
symbol encoding by tree search and tree generation by successive merging.

Some files are not tests: the picture-language exercises draw, the queue
exercises print, and the generic-arithmetic files only define the system. The
digital-circuit files 3.28-3.30 are sketches of the book's design and do not run
as committed. Prose-only exercises are not included, and the chapter 3 work
continues.
