I reimplemented the nm tool for the École 42 nm project. ft_nm maps an ELF file
with mmap, locates the .symtab section and its string tables through the section
header table, decodes every symbol and prints the same listing GNU nm prints: an
8- or 16-digit hexadecimal address (or blanks for undefined symbols), a one-
letter type, and the name, sorted the way nm sorts.

Two decisions shaped the code. The first was to write the parser once for both
ELF classes: the section lookup, symbol decoding and list building are macros
instantiated for 32 and 64 with the Elf32_ and Elf64_ types from elf.h, so there
is a single place to fix when something is wrong. The second was to make symbol
classification a table rather than a chain of conditionals. Each rule lists a
binding, a type, a section index, a section type, required and forbidden section
flags and a section name, with -1 as a wildcard, and get_sym_type returns the
letter of the first rule that matches. Weak, undefined, bss, text, read-only
data and data symbols are all covered by rows in that table.

Matching nm's ordering took a while: names are compared after removing
underscores, at signs and dots and lower-casing, with the address as a tie-
breaker. Error handling follows nm's format on stderr, and the section header
table is bounds-checked against the file size so truncated headers give an error
instead of a crash. The tests directory holds hand-crafted ELF files for exactly
those cases, plus a script that diffs my output against the system nm on any
binary.

The Makefile generates dependency files with gcc -M, and the sources are
formatted with a checked-in clang-format configuration. Limitations: only native
little-endian files, no command-line options, offsets inside individual sections
are not bounds-checked, and the sort is a bubble sort.
