lemipc is my École 42 lem_ipc project: a team game on a 20x20 board where every
player is a separate process and the only communication channel is System V IPC.
Each `lemipc <team_id>` process joins the board, hunts the nearest enemy every
half second, and is eliminated when two members of the same enemy team surround
it. A separate `lemipc_display` program attaches to the same shared memory and
draws the board with SDL2.

The whole game state is one shared memory segment holding the player count and
the board, guarded by a single System V semaphore used as a mutex. I wrapped the
lock in `with_data()`, which takes a function pointer and runs it between the P
and V operations, so joining, taking a turn and leaving are critical sections by
construction. Creating the IPC objects without a coordinator was the fiddly
part: each process first tries to open existing objects and only then creates
them with `IPC_CREAT | IPC_EXCL`, rolling back anything already created if a
later step fails; the kernel's zero-fill of a fresh segment doubles as board
initialisation. The last player to leave removes all three objects.

Teams coordinate through a message queue where the message type is the team id,
so `msgrcv` with `IPC_NOWAIT` hands each player only its own team's messages. A
player that spots a target posts it; teammates verify the cell still holds that
enemy before following, so the team converges on one target. Movement is a
greedy step along the dominant axis with a side-step when blocked, bounds-
checked before the board is touched. SIGINT only flips a flag, so shutdown goes
through the normal leave path.

The build uses `-Wall -Wextra -Werror` with automatic dependency files, and a
Python launcher starts a display plus any number of players per team and
forwards Ctrl-C to all of them. Limitations: the display reads the board without
the lock, a winner check is declared but never implemented, two players started
at the same instant can lose the creation race, and there are no automated
tests.
