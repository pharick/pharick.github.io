I built nibbler after the École 42 subject of the same name: a Snake game where
the graphics have to live in several independently compiled dynamic libraries
that can be swapped while the game runs. The executable contains only the game
logic and a loader; the three renderers (SDL2, SFML 3 and OpenGL 3.3 core) are
shared objects built by their own Makefiles.

The interesting part is the boundary. I kept the interface to one abstract
class, `ALibGUI` with `render` and `handleInput`, plus two `extern "C"` factory
functions, `createGuiLibrary` and `destroyGuiLibrary`. The loader only ever
touches those two C symbols with `dlsym`, so no mangled C++ name crosses the
library boundary, and the game and the renderers share nothing but two POD
structs (`Segment` and `Input`). Switching is done by destroying the renderer
through the library's own destroy function, `dlclose`, then `dlopen` of the next
one; the `Snake` object is untouched, so the board continues where it was.

The OpenGL renderer took the most work: every cell is a unit cube drawn from one
VBO, positioned with GLM model and perspective matrices so the field exactly
fills the view at a fixed camera distance, and coloured in the fragment shader
from the segment index with a sine gradient. The projection is rebuilt in the
resize callback; the SDL and SFML renderers recompute cell size on resize as
well.

Game logic is small and deliberately isolated: a `std::vector<Segment>`, a
direction with reversal lockout, wall and self collision reported as an
exception that the main loop turns into a reset, and food placed with
`std::mt19937` until it lands on a free cell.

Everything compiles with `-Wall -Wextra -Werror -std=c++20 -fPIC` and generated
header dependencies. Limitations: the Makefiles hard-code Homebrew paths and
`-framework OpenGL`, so the build as written is macOS-only; an exception thrown
while a renderer initialises is not caught in `main`; there is no score or speed
change and no automated tests.
